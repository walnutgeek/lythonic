# v0.0.29

## New

- `lythonic.compose.namespace`: a node can declare one opaque requirement,
  `requires: str | None`, which the host enforces. woodglue, for example, uses
  it as the node's Required Action, such as `"write"`. Lythonic only stores it
  in `NsNodeConfig.requires` and exposes it as `NamespaceNode.requires`. It can
  be set with `@nsnode(requires=...)` on fragment classes and modules, with
  `Namespace.register(..., requires=...)` for callables, DAGs and DAG
  factories, with `register_all(..., requires=...)`, and as `requires:` on a
  YAML / `from_dict` entry. It round-trips through `to_dict()`. If the
  `requires` argument and a passed config's `requires` differ, `register`
  raises `ValueError`. Unlike `tags`, the config does not silently win.
  `requires` is unrelated to `@mount_required`.

## Changed

- `lythonic.compose.namespace`: `Namespace.register` claims a DAG
  (`dag.parent_namespace`) only after its node is built. A DAG registration
  rejected for a duplicate nsref or a conflicting `requires` can now be retried.
  Previously the retry failed with "already registered".

## Documentation

- The namespace module docs gain a "Requires" section, and the glossary defines
  "Requirement".
